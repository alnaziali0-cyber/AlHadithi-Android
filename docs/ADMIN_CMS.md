# دليل CMS الإداري — خزائن الهدى

## الوصول والحماية

جميع عمليات الإدارة تحت `/api/v1/admin` وتتطلب جلسة مدير صالحة. المستخدم الإداري يجب أن يكون نشطاً ومن دور `owner`، ويجب إتمام تغيير كلمة المرور الأولية قبل استخدام CMS. طلبات `POST` و`PUT` و`DELETE` تتطلب رمز CSRF المطابق لملف الارتباط ورأس `X-CSRF-Token`. عمليات الإنشاء والتعديل والأرشفة واستيراد الصفحات وإضافة التقييمات تسجل في `admin_audit_logs` ضمن المعاملة نفسها.

لا توجد مفاتيح أو كلمات مرور مضمنة في واجهة CMS. لوحة الإدارة تستخدم الجلسة وCSRF ولا تخزن كلمة المرور في JavaScript.

## أقسام السجل المدعومة

القيمة في `{catalog_type}` يجب أن تكون واحدة من:

- `book`
- `hadith_source`
- `hadith`
- `dua`
- `visit`
- `event`
- `ethics_lesson`
- `audio`

المسارات:

| الطريقة | المسار | الغرض |
|---|---|---|
| GET | `/api/v1/admin/catalog/{catalog_type}?limit=50&offset=0` | عرض سجلات القسم بما فيها المسودات |
| POST | `/api/v1/admin/catalog/{catalog_type}` | إنشاء سجل |
| PUT | `/api/v1/admin/catalog/{catalog_type}/{id}` | استبدال بيانات السجل وفق مخطط النوع |
| DELETE | `/api/v1/admin/catalog/{catalog_type}/{id}` | أرشفة منطقية، دون حذف مادي |
| POST | `/api/v1/admin/hadith/{id}/gradings` | إضافة تقييم علمي جديد للرواية |
| GET | `/api/v1/admin/books/{id}/pages` | عرض صفحات الكتاب للإدارة |
| POST | `/api/v1/admin/books/{id}/pages` | استيراد دفعة صفحات (حتى 250 صفحة لكل طلب وبحد إجمالي نصي مليوني محرف) |
| PUT | `/api/v1/admin/books/{id}/pages/{volume}/{page}` | تعديل نص صفحة غير منشورة |

`hadith_source` سجل ببليوغرافي مرجعي؛ لا يسمح مسار DELETE بأرشفته كي لا تُكسر الإحالات. يمكن تصحيح بيانات المصدر عبر PUT. لا يوجد حذف مادي من واجهة CMS.

## قواعد الاعتماد والنشر

- **الكتب:** النشر يشترط `rights_status` من `licensed` أو `public_domain` أو `permission_granted`، ودليل حقوق غير فارغ، ورابط مصدر HTTPS. يجب أرشفة الكتاب قبل تغيير مجموعة صفحاته أو نصوصها.
- **مصدر الرواية:** يجب إدخال اسم المصدر وبيانات الطبعة قبل نشر رواية مرتبطة به.
- **الروايات:** النشر يشترط رقم الرواية أو بيانات المجلد والصفحة، إضافة إلى مصدر له طبعة مسجلة. لا يعني النشر ثبوت الرواية.
- **تقييم الرواية:** يضاف كسجل مستقل يذكر التقييم والباحث والمنهج والإحالة. الإضافة تراكمية ولا تستبدل نص الرواية أو سندها.
- **الأدعية والزيارات:** النشر يشترط مرجعاً نصياً للمصدر.
- **المناسبات:** النشر يشترط مصدراً تاريخياً واحداً على الأقل وتاريخاً هجرّياً كاملاً أو تاريخاً ميلادياً متوقعاً. تحفظ درجة اليقين كما أدخلها المحرر.
- **دروس الأخلاقيات:** النشر يشترط مرجعاً قرآنياً أو رابطاً برواية مسجلة.
- **الصوتيات:** النشر في كتالوج الصوت العام يشترط حقوقاً معتمدة ودليل حقوق ورابط HTTPS وإذن البث. التنزيل ميزة إضافية تتطلب رابط تنزيل مستقلاً وإذن التنزيل، والتخزين دون اتصال يتطلب إذن التنزيل أيضاً.

كل مخططات الإدخال ترفض الحقول غير المعروفة. قيم الروابط تقبل HTTPS فقط ولا تسمح ببيانات اعتماد ضمن الرابط. علاقات الفئات والمصادر والرواة والروايات المرجعية تتحقق على الخادم قبل الحفظ.

## استيراد صفحات كتاب

مثال جسم طلب POST:

```json
{
  "pages": [
    {
      "volume_number": 1,
      "page_number": 1,
      "text_content": "النص المستورد من النسخة المرخصة"
    },
    {
      "volume_number": 1,
      "page_number": 2,
      "text_content": "النص التالي من المصدر نفسه"
    }
  ]
}
```

كل صفحة يجب أن تحمل رقماً موجباً ومحتوى غير فارغ لا يتجاوز 25,000 محرف. يقتصر الطلب على 250 صفحة وبحد إجمالي 2,000,000 محرف، كما لا يسمح بمجلد يتجاوز عدد مجلدات الكتاب المسجل. تمنع الواجهة تكرار زوج المجلد/الصفحة داخل الطلب، وتفرض قاعدة البيانات تفرد `(book_id, volume_number, page_number)` عبر الطلبات أيضاً. الاستيراد معاملاتي: عند تعارض سجل واحد يُرفض الطلب كله ولا يبقى جزء من الدفعة.

## واجهة الإدارة الحالية

تحتوي لوحة الإدارة تبويباً بعنوان «المكتبة والمحتوى الموثّق» يدعم إنشاء السجل وتحريره وأرشفته عبر محرر JSON مضبوط بمخططات الخادم. توجد نماذج مرتبطة لاستيراد صفحات الكتب وإضافة تقييمات الروايات. هذه واجهة CMS أولية وظيفية وليست بعد محرراً غنياً خاصاً بكل نوع، ولا توفر سير موافقات متعدد المراجعين أو أدواراً تحريرية دقيقة.

## أمثلة طلب

إنشاء مصدر حديثي:

```json
{
  "title": "عنوان المصدر كما في الطبعة",
  "author": "اسم المؤلف",
  "edition": "بيانات الطبعة",
  "source_url": "https://publisher.example/source",
  "citation_policy": "اذكر الجزء والصفحة أو رقم الرواية"
}
```

إضافة تقييم:

```json
{
  "grading": "غير محسوم",
  "scholar": "اسم الباحث",
  "methodology": "المنهج المتبع",
  "citation": "الإحالة العلمية الدقيقة"
}
```

هذه الأمثلة توضح شكل البيانات فقط؛ لا تمثل مصادر حقيقية أو محتوى دينياً صالحاً للنشر.

### الإذاعة والبث المباشر

لا يكفي وضع `is_verified=true` أو وجود رابط يعمل لتفعيل محطة. يجب إدخال `rights_evidence` يتضمن مرجع الإذن أو الترخيص، الجهة المانحة، تاريخ الإذن، ونطاق الاستخدام المسموح (بث داخل التطبيق، تنزيل، تخزين مؤقت أو إعادة استضافة كلٌ على حدة). عند حفظ حالة التحقق يخزن الخادم `rights_reviewed_at`. ترحيل 0006 يعيد القنوات القديمة إلى غير موثقة/غير مفعلة حتى يعاد تدقيقها. دليل الحقوق لا يظهر في واجهة المستخدم العامة.


## إدارة الخلفيات المحلية

يعرض تبويب «الخلفيات» الصور المحددة مسبقاً والمضمّنة في تطبيق الهاتف. لا يقبل هذا القسم رفع ملفات أو إدخال مسارات صور/روابط خارجية. تظل الصورتان في أصول الهاتف المحلية، ويقتصر الخادم على حفظ حالة النشر في `app_settings`.

- `GET /api/v1/admin/wallpapers` يعرض سجل الصور وحالة النشر للمالك المسجل بعد تغيير كلمة المرور الأولية.
- `PUT /api/v1/admin/wallpapers/{wallpaper_id}` يغيّر حالة صورة معرّفة حصراً في الكتالوج الثابت، ويتطلب جلسة مالك صالحة ورمز CSRF.
- `GET /api/v1/public/wallpapers` يعرض معرّفات الصور المنشورة فقط، ولا يعيد عناوين المصدر أو روابط خارجية أو مسارات قابلة للتحكم.

تُسجّل عمليات النشر والإخفاء في `admin_audit_logs`. يمزج تطبيق الهاتف هذه الحالة مع سجل الصور المحلي ويخزن آخر قائمة معروفة لعرضها دون اتصال؛ أي تغيير إداري جديد يصل إلى الهاتف عند مزامنة حالة الكتالوج، بينما ملف الصورة نفسه لا يُطلب من الشبكة مطلقاً. راجع `apps/mobile/assets/data/WALLPAPERS_RIGHTS_NOTICE_AR.md` لإسناد المصورين وشروط التراخيص وبصمات الملفات.
