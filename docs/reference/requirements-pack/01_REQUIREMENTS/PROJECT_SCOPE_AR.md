# وثيقة نطاق المشروع – مرحلة المكتبة الصوتية والإذاعات والمواقيت

## الهدف
إضافة منظومة محتوى منظمة وقابلة للإدارة إلى تطبيق «خزائن الهدى»، مع فصل بيانات المحتوى عن الملفات الكبيرة، وإدارة الحقوق بصورة صريحة، وإتاحة إعدادات مواقيت الصلاة حسب المرجع أو التقويم الذي يختاره المستخدم.

## أقسام التطبيق

### A. الأذان والمؤذنون
- تصنيف التسجيلات: أذان عام، أذان الفجر، تسجيلات خاصة بمؤذن.
- بيانات المؤذن: الاسم، الاسم البديل، نبذة مختصرة، صورة مصرح بها، الجهة، بلد/مدينة (اختياري)، روابط المصادر.
- بيانات التسجيل: العنوان، نوع الأذان، اللغة، المدة، تنسيق الملف، معدل البت، حجم الملف، مصدر التسجيل، تاريخ الإضافة.
- دعم الاستماع والبث والتنزيل فقط وفق أذونات الترخيص.

### B. القرآن والقراء
- القارئ، الرواية/القراءة عند توثيقها، السورة أو الجزء، رقم الآية أو نطاق الآيات إن توفر.
- تجميع المصحف الكامل أو السور المنفردة.
- دعم قوائم التشغيل، استكمال الاستماع، وسرعة التشغيل.
- عدم افتراض صحة نسبة التلاوة إلى قارئ إلا بعد مراجعة المصدر.

### C. المجالس الحسينية والمحاضرات واللطميات والزيارات والأدعية
- الخطيب/الرادود/المنشد/القارئ، العنوان، المناسبة، السنة أو التاريخ، المكان عند توفره.
- تصنيف المحتوى: مجلس، محاضرة، لطميّة، دعاء، زيارة، مادة تعليمية.
- بيانات مناسبة هجرية وميلادية قابلة للفصل حتى لا تختلط التواريخ.
- فصل المواد الصوتية عن الصور المصاحبة.

### D. الإذاعات والبث المباشر
- بيانات المحطة: الاسم الرسمي، وصف، شعار، صورة، الجهة المالكة، الموقع الرسمي، الترددات حسب المدينة عند توفرها.
- بيانات البث: عنوان رابط البث الرسمي، البروتوكول (HLS/AAC/MP3/غير ذلك)، المنطقة، آخر فحص، حالة الاتصال.
- لا تستخرج رابط stream من تطبيق أو صفحة دون إذن؛ اطلب رابط تضمين رسمي.
- دعم بث الخلفية والتحكم من شاشة القفل فقط بعد اختبار المشغّل وحقوق البث.
- لا تسجل البث أو تعيد توزيعه إلا إذا كان الترخيص يسمح بذلك صراحة.

### E. الشعارات والصور الرسمية
- الاحتفاظ بالنسخة الأصلية وبنسخ العرض المصغرة.
- تسجيل الجهة المالكة، مصدر الصورة، شروط النسبة، وحدود الاستخدام.
- عدم إزالة العلامة المائية أو إعادة رسم شعار جهة دون إذن.

### F. مواقيت الصلاة الجعفرية
- اختيار المدينة أو GPS مع طلب إذن الموقع.
- المنطقة الزمنية `Asia/Baghdad` للعراق، مع الاعتماد على قاعدة IANA للمناطق الزمنية وعدم إضافة ساعة ثابتة يدوياً.
- ملف حساب مستقل لكل مرجع/تقويم موثق.
- إظهار اسم ملف الحساب والجهة المرجعية ومصدر البيانات للمستخدم.
- توفير تعديلات يدوية بالدقائق مع توضيح أنها تعديل المستخدم وليست جزءاً من المرجعية.
- عرض الفجر، الشروق، الظهر، الغروب، المغرب، العشاء إن كان المصدر/المنهج يعتمده، ومنتصف الليل الشرعي والفلكي عند توفرهما.
- المقارنة بين أكثر من مدينة مع حفظ تاريخ الحساب وإصدار المحرك.

## متطلبات إدارية
- لوحة CMS لإضافة/تعديل/أرشفة المحتوى.
- مراجعة قبل النشر: `draft -> pending_review -> approved -> published`.
- حظر النشر عند غياب إثبات الحقوق أو انتهاء الترخيص.
- سجل تدقيق لمن أضاف أو عدّل أو وافق.
- واجهة لإدارة الملفات والفئات والقراء والمؤذنين والمحطات والمدن وملفات الحساب.

## متطلبات غير وظيفية
- الملفات الكبيرة في Object Storage وليس PostgreSQL.
- تخزين metadata في PostgreSQL.
- استخدام روابط موقعة قصيرة العمر للمواد الخاصة أو المدفوعة عند الحاجة.
- دعم الاستئناف والتنزيل الجزئي حيث تسمح البنية.
- تقييد أنواع الملفات وحجمها وفحص الملفات قبل قبولها.
- عدم كشف مفاتيح التخزين أو روابط الإدارة داخل تطبيق Flutter.
- تسجيل أخطاء البث والتنزيل ومراقبة صلاحية الروابط.
- نسخ احتياطي لقاعدة البيانات وبيانات التراخيص.

## شروط قبول المرحلة
1. يمكن إضافة مادة وتصنيفها وربطها بصاحب حقوق وترخيص.
2. لا يمكن نشر مادة حالة حقوقها `pending` أو `restricted`.
3. يعمل البث الرسمي في التطبيق عند توفر رابط مصرح به.
4. التنزيل والتشغيل دون إنترنت لا يعملان إلا للمحتوى المسموح به.
5. يمكن للمستخدم اختيار مدينة وملف مواقيت موثق.
6. تظهر معاملات ملف المواقيت ومصدره ولا تُخلط ملفات المراجع.
7. تتم مقارنة نتائج المواقيت بجدول مرجعي موثق لمدن العراق قبل الإطلاق.
8. تتوفر سجلات تدقيق لقرارات النشر والتعديل.
