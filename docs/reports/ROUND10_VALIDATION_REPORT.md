# تقرير التحقق الهندسي — الجولة العاشرة

**التاريخ:** 14 نوفمبر 2026  
**النطاق:** تطبيق Flutter، خدمة API، جدول تنبيهات الصلاة، أصول الخط القرآني، وسجل مصادر المحتوى.

## نتيجة التحقق

| الفحص | النتيجة | التفاصيل |
|---|---|---|
| اختبارات API | ناجح | 31 اختباراً من 31 (`31 passed`). |
| تجميع Python | ناجح | `python -m compileall -q app tests scripts` من مجلد `services/api`. |
| ملفات JSON | ناجح | تم تحليل ملفات JSON الموجودة والتحقق من سلامة صياغتها. |
| ملفات CSV | ناجح | تمت قراءة ملفات CSV والتحقق من اتساقها البنيوي. |
| YAML / pubspec | ناجح | تمت قراءة `pubspec.yaml` والتحقق من الاعتماديات ومسار الخط. |
| مراجع Dart المحلية | ناجح | فحص ساكن لمسارات الاستيراد النسبية في ملفات Dart الموجودة تحت `lib/`. |
| ملف Amiri Quran | ناجح | تم التعرف على الخط واسم العائلة `Amiri Quran` عبر `fc-scan`؛ ملف OFL مرفق. |
| Flutter / Dart build | غير منفذ | لا توجد أداة Flutter أو Dart في بيئة إعداد الأرشيف. |
| Flutter analyzer / tests | غير منفذ | لم يمكن تشغيل `flutter analyze` أو `flutter test` دون SDK. |
| APK / IPA | غير منفذ | مجلدا `android/` و`ios/` غير موجودين في المصدر الوارد، ولا تتوفر بيئة بناء iOS/Xcode. |
| اختبار تنبيهات على جهاز حقيقي | غير منفذ | يتطلب توليد ملفات المنصات، دمج الإعدادات، وتثبيت التطبيق على أجهزة فعلية. |

## ما أصبح قابلاً للاستخدام في الشفرة

1. خيار اختياري لتفعيل تنبيهات الصلاة من صفحة الإعدادات بعد طلب إذن النظام.
2. جدولة محلية متجددة لأربعة أوقات متاحة في المحرك الحالي (الفجر والظهر والمغرب والعشاء) لمدة 14 يوماً وبحد أقصى 56 إشعاراً.
3. تطبيق تعديلات الدقائق المحلية، واستخدام المنطقة الزمنية المختارة، وحذف الإشعارات القديمة عند الإيقاف أو فشل الحساب.
4. تفضيل Exact Alarm عند توافر الإذن والرجوع إلى الجدولة غير الدقيقة عند عدم توافره.
5. إعادة المزامنة عند الرجوع للتطبيق وتغير المواقيت أو فروقات الدقائق.
6. تضمين خط `Amiri Quran` ورخصة SIL OFL 1.1 وتطبيق الخط على نص الآيات في العارض.
7. توسيع سجل المصادر مع حفظ حالة الترخيص والقيود بدلاً من اعتبار وجود المصدر إذناً عاماً بإعادة النشر.

## قيود لا يجوز اعتبارها منجزة

- **صوت الأذان الكامل:** التنبيه الحالي يستخدم صوت إشعار النظام؛ لا يشغّل ملف MP3 كاملاً عند إغلاق التطبيق أو قفل الشاشة. يلزم تنفيذ خدمة أصلية مدروسة لكل منصة واختبارات خاصة بها.
- **اكتمال المنصات:** يجب توليد Android وiOS ودمج أذونات الإشعارات والمستقبلات/المستمعين وفق `docs/PLATFORM_NOTIFICATIONS_SETUP_AR.md`، ثم تشغيل بناء نظيف.
- **مدة الجدولة:** تُحضّر نافذة 14 يوماً عند فتح التطبيق/عودته أو عند تغيير الإعدادات؛ لا توجد مهمة خلفية مضمونة لإعادة ملئها يومياً، وقد تنفد الإشعارات بعد 14 يوماً إذا لم يُفتح التطبيق.
- **تغطية الصلوات:** لا يوجد وقت عصر موثوق ضمن البيانات التي يوفرها المحرك الحالي، لذلك لم يُنشأ تنبيه عصر تقديري.
- **نص القرآن:** أضيف الخط ومصدر النص وشروطه، لكن نص المصحف نفسه لم يُضمّن؛ يجب إدخال نسخة Tanzil بنيويتها الصحيحة ثم اجتياز الاستيراد والمراجعة الشرعية وتسجيل بصمة SHA-256 المعتمدة.
- **الكتب والتسجيلات:** سُجلت مصادر OpenITI وAQQD للمراجعة، لكن لم تُنسخ كتب أو تلاوات جديدة إلى التطبيق لعدم اكتمال إثبات حقوق كل طبعة/تسجيل. لا تكفي إتاحة الملف على الإنترنت دليلاً على حق إعادة توزيعه.
- **MP3 المرفق أصلاً:** بقي كما ورد من مالك المشروع؛ البيانات الوصفية لا تثبت بذاتها حق إعادة توزيعه.
- **اعتماد المواقيت:** طرق الحساب وإحداثيات مراكز المدن تحتاج مقارنة واعتماداً من جهة جعفرية محلية قبل طرحها كمرجع معتمد.

## خطوات الإطلاق التالية

1. توليد المنصتين في نسخة عمل منفصلة، ثم تطبيق إعدادات `docs/PLATFORM_NOTIFICATIONS_SETUP_AR.md` ومراجعة Gradle / Xcode.
2. تثبيت الاعتماديات وتشغيل `flutter analyze` و`flutter test` وبناء APK؛ وبناء IPA على macOS مع Xcode.
3. اختبار الإشعارات بعد إعادة تشغيل الجهاز، رفض الأذونات، إيقاف التطبيق، تغيّر المنطقة الزمنية، وضع توفير الطاقة، وتغيّر المحافظة/المدينة.
4. تحديد متطلب مستقل لتشغيل الأذان الكامل بالخلفية، مع ملف صوت مرخص وخدمة أصلية وسياسة متجر مناسبة؛ لا تخلط هذا بجدولة الإشعار المحلي.
5. استلام ملف نص Tanzil والبيانات البنيوية ومراجعتهما، ثم اعتماد البصمة في سجل المشروع قبل تفعيل المصحف.
6. مراجعة كل كتاب/طبعة/تسجيل على حدة وإرفاق ملف الترخيص والنسبة وسلسلة مصدر المحتوى قبل النشر.
