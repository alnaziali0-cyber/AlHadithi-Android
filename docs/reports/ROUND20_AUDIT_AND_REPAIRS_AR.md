# تقرير التدقيق والإصلاح — Round 20

**التاريخ:** 16 نوفمبر 2026  
**الملف المدخل:** `khazain-al-huda-round19-updated (1).zip`  
**النتيجة:** اجتازت اختبارات Backend وفحوص سلامة الموارد والترحيلات. ما زالت النسخة **غير جاهزة للنشر** بسبب غياب منصات الهاتف الأصلية وملفات الصوت المحلية واختبارات Flutter والجهاز.

## 1. نطاق التدقيق

فُك الأرشيف المرفوع وفُحصت بنية التطبيق، ملفات Flutter وDart المتاحة، خدمة FastAPI، مخططات SQLAlchemy وترحيلات Alembic، لوحة الإدارة، بيانات المصحف، ملفات JSON وZIP، سجل مصادر الصوتيات، ملفات التراخيص والوثائق. لم يتم استبدال أو حذف محتوى ديني محمي ولم تُنشأ تسجيلات وهمية لسد النقص.

## 2. الإصلاحات المنفذة

### حماية تفعيل البث الإذاعي

- أضيف `rights_evidence` و`rights_reviewed_at` إلى سجل `RadioChannel`.
- أضيفت ترحيلة Alembic رقم `0006_radio_rights_evidence`.
- لم يعد ممكناً التحقق من محطة أو تفعيلها دون رابط بث HTTPS، ومصدر رسمي HTTPS، ودليل إذن إعادة استخدام موثق.
- يعيد الترحيل القنوات الموجودة سابقاً إلى غير موثقة وغير مفعلة؛ يجب على المشرف مراجعة كل محطة وإعادة حفظ دليلها قبل استئناف البث.
- لا يعيد المسار العام عرض محطة حتى لو كانت أعلام قاعدة البيانات مفعلة يدوياً، ما لم يوجد دليل الإذن وتاريخ مراجعته.
- لا يرسل API دليل الحقوق الداخلي إلى المستخدمين.
- أضيف حقل الدليل إلى لوحة الإدارة وسجل التدقيق، وأضيف اختبار يمنع الدليل المفقود أو القصير ويحاكي سجلاً قديماً غير موثق.

### مشغل الراديو في Flutter

- يرفض روابط البث ومواقع المحطات غير HTTPS أو التي تحتوي بيانات اعتماد مضمنة.
- يعالج فشل فتح المصدر الرسمي وفشل التشغيل برسالة للمستخدم بدلاً من ترك استثناء ظاهر.
- أصلح انتظار `play()` الطويل: يبدأ البث دون إبقاء واجهة التشغيل في حالة تحميل حتى انتهاء البث، وبذلك يبقى زر الإيقاف متاحاً أثناء البث الحي.

### التوثيق والتحقق الآلي

- صُححت سياسة التراخيص لتصف ملف Tanzil Simple/Imla'ei المستخدم فعلياً، وتفصل عنه ملف Quran.ws التاريخي غير المستخدم.
- صُححت وثائق البدء والتسليم كي لا تدّعي وجود MP3 محلي أو تشغيل أذان كامل.
- وُسِم تقرير الجولة السابعة بأنه تقرير تاريخي حتى لا يُخلط مع الحالة الحالية.
- أضيف `scripts/audit_project.py` لفحص JSON وبصمات المصحف وبنية الآيات وأرشيفات ZIP وحقوق فهرس الصوتيات وأصول Flutter وسلسلة الترحيلات.
- أضيف `scripts/run_local_checks.sh` لتشغيل فحوص الأصول وPython وJavaScript والاختبارات، وتشغيل Flutter pub get/analyze/test عند توفر SDK.
- أضيف GitHub Actions workflow لتشغيل فحوص Backend، والترحيلات، وتحليل Flutter واختباراته في بيئة CI.

## 4. النواقص والقيود المؤكدة

1. **Flutter وDart SDK غير متوفرين في بيئة التدقيق.** لذلك لم يتم تنفيذ `flutter pub get` أو `flutter analyze` أو `flutter test` محلياً، ولم يُبنَ APK أو AAB أو IPA. أضيفت هذه الخطوات إلى سكربت الفحص وCI لتعمل عند توفر البيئة.
2. **مجلدا `apps/mobile/android/` و`apps/mobile/ios/` غير موجودين في الأرشيف.** لا توجد ملفات Manifest أو Info.plist فعلية يمكن تعديلها هنا. يجب توليد المنصات بأمر Flutter الموضح في README، ثم تطبيق الأذونات والاسم ومعرّفات التطبيق والتوقيع.
3. **عدد الملفات الصوتية المحلية الفعلية: صفر.** فهرس الصوتيات يحوي 23 مرجعاً/رابطاً خارجياً فقط. مشغل المصحف يستدعي تلاوة العفاسي من مزود CDN ويسمح بتنزيل سورة بطلب المستخدم وفق شروط المزود؛ هذا ليس تصريحاً بإعادة توزيع التسجيل تجارياً.
4. **لا توجد تسجيلات أذان أو لطميات أو مجالس أو نواعي أو مواليد مرفقة محلياً.** لم تُسحب مواد محمية أو غير واضحة الترخيص.
5. **الإذاعة غير مفعلة افتراضياً.** بعد الترحيل 0006 يجب على المسؤول التحقق من رابط البث وإرفاق دليل إذن يغطي نطاق الاستخدام المقصود.
6. **المكتبة العلمية غير مكتملة المحتوى.** توجد نماذج CMS وجداول وفهارس ومصادر؛ لكن لا توجد مجموعة منشورة مكتملة وموثقة من التفاسير والكتب والأحاديث والأدعية والزيارات. بعض المواد تحتاج ترخيصاً أو إذناً ومراجعة مختصين.
7. **واجهة Quran API في الخادم لا تزال مغلقة حتى استيراد ومراجعة نسخة Uthmani منفصلة.** وجود نص محلي في تطبيق الهاتف لا يعني أن جدول المصحف في قاعدة بيانات API جاهز.
8. **مواقيت الصلاة والمناسبات تحتاج اعتماداً محلياً.** سجلات المدن تقريبية، وطريقة الحساب المعلنة تحتاج مقارنة واعتماداً من مرجع/جهة جعفرية محلية قبل الاستخدام الفقهي الإنتاجي.
9. ملفات `README_PLACEHOLDER.txt` الأربع والعشرون في `docs/reference/requirements-pack/` قوالب فارغة موروثة من حزمة المتطلبات؛ ليست ملفات تطبيق فعالة ولا تمثل ملفات صوتية مكتملة.

القائمة الآلية التفصيلية موجودة في `ROUND20_MISSING_ITEMS.json`، ويُلخص `docs/reports/DELIVERY_MANIFEST.md` محتويات التسليم.

## 5. تعليمات الترقية والتشغيل

بعد نسخ المصدر إلى بيئة المشروع:

```bash
# API — من جذر المشروع
python -m pip install -r services/api/requirements.txt
pytest -q
bash scripts/run_local_checks.sh

# قاعدة البيانات — من services/api
alembic upgrade head
alembic check
```

**تنبيه ترحيل:** Migration `0006_radio_rights_evidence` يعطل محطات الراديو القديمة حتى يُراجع دليل إعادة استخدامها. هذا سلوك مقصود fail-closed لمنع بث مصدر من دون إذن محفوظ.

لتجهيز منصات الهاتف بعد تثبيت Flutter:

```bash
cd apps/mobile
flutter create --platforms=android,ios --org org.khazainalhuda --project-name khazain_al_huda .
flutter pub get
flutter analyze
flutter test
```

بناء iOS يحتاج macOS وXcode. ثم يجب إضافة أذونات الموقع والإشعارات والصوت حسب الميزات المستخدمة، وتجهيز اسم التطبيق وأيقوناته ومفاتيح التوقيع، واختبار الإذن/الرفض والخلفية والصوت على أجهزة فعلية.
