# المكتبة الشخصية على الجهاز

## الوظائف

توفّر النسخة الحالية المفضلة وموضع قراءة الكتب دون مطالبة المستخدم بإنشاء حساب:

- حفظ الكتب والروايات والأدعية والزيارات والمناسبات ودروس الأخلاقيات والصوتيات المسموح بنشرها.
- رفض حفظ أي عنصر غير منشور أو لا يجتاز بوابة المصدر وحقوق الاستخدام المعمول بها في الفهرس العام.
- عرض العناصر المسحوبة من النشر بوصفها غير متاحة، مع السماح بإزالة سجلها من المفضلة.
- حفظ آخر موضع قراءة لكل مجلد من الكتاب، بعد التحقق من وجود الصفحة فعلياً.
- حفظ علامة الآية القرآنية باستخدام نوع المفضلة `quran_ayah` ومعرّف `surah:ayah`، بعد أن يثبت الخادم وجود الآية ضمن استيراد كامل ومعتمد.
- تخزين صفحات الكتاب دون اتصال فقط عند وجود إذن مستقل وصريح للتخزين المحلي، وليس بمجرد السماح بالنشر أو القراءة عبر الإنترنت.
- الاحتفاظ بآخر موضع قراءة محلياً، وإعادة محاولة مزامنته مع الخادم عند عودة الاتصال.

## واجهات API

كل واجهات المكتبة الشخصية تتطلب الرأس `X-Device-Key`:

| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET | `/api/v1/user/favorites` | استرجاع مفضلة التثبيت الحالي |
| POST | `/api/v1/user/favorites` | إضافة عنصر موثق للمفضلة |
| DELETE | `/api/v1/user/favorites/{entity_type}/{entity_id}` | إزالة عنصر |
| GET | `/api/v1/user/books/{book_id}/reading-progress` | استرجاع آخر موضع قراءة |
| PUT | `/api/v1/user/books/{book_id}/reading-progress` | حفظ موضع قراءة موجود فعلياً |

أنواع المفضلة المدعومة: `book`, `hadith`, `dua`, `visit`, `event`, `ethics_lesson`, `audio`, `quran_ayah`. بالنسبة للآية، يكون `entity_id` بصيغة `surah:ayah` مثل `2:255`، ويتحقق الخادم من الاعتماد والوجود قبل الحفظ.

قيمة `X-Device-Key` سلسلة عشوائية URL-safe بطول 32 إلى 128 محرفاً. ينشئ العميل Flutter قيمة 256-bit من `Random.secure()` ويحفظها في `SharedPreferences` على الجهاز؛ هذا التخزين المحلي غير مشفر، ولذلك لا تُعامل القيمة كسرّ مصادقة ولا كوسيلة لحماية بيانات شخصية. إذا تعذر حفظ التفضيل، يبقيها العميل في الذاكرة حتى إغلاق العملية، وقد تتغير مساحة البيانات بعد إعادة تشغيل التطبيق. يحوّل الخادم القيمة إلى HMAC-SHA256 باستخدام `APP_SECRET` قبل تخزينها. لا تُخزّن القيمة الخام في قاعدة البيانات.

**حدود الثقة:** مفتاح الجهاز معرّف مساحة بيانات مجهول منخفض الحساسية، وليس وسيلة مصادقة أو إثبات هوية أو تفويض للوصول إلى بيانات خاصة. يستطيع من يملك المفتاح قراءة أو تعديل مفضلة وموضع القراءة المرتبطين به فقط. لا تضع معلومات شخصية أو سرية في هذه المسارات. لا تدعم هذه النسخة مزامنة المفضلة بين أجهزة مختلفة أو ربطها بحساب. عند إضافة الحسابات لاحقاً يجب تنفيذ نقل ملكية ذري بمصادقة حقيقية وإبطال جلسات، لا ترقية مفتاح الجهاز إلى رمز دخول.

## الترحيلات والقيود

- `0003_device_library_state` يضيف جدول `book_reading_progress` وفهرساً جزئياً فريداً يمنع تكرار مفضلة الجهاز حتى مع كون `user_id` فارغاً في PostgreSQL.
- `0004_book_offline_access` يضيف `books.offline_access_allowed` كإذن مستقل افتراضه `false`، ولا يمكن تفعيله من CMS إلا مع حالة حقوق معتمدة ودليل حقوق ورابط مصدر HTTPS.
- موضع القراءة يُحفظ فقط إذا كان الكتاب منشوراً ومصدره وحقوقه موثقين والصفحة المطلوبة موجودة في نفس المجلد.
- إزالة النشر بعد الحفظ لا تحذف المفضلة تلقائياً؛ يعرضها API كعنصر غير متاح ولا يعيد محتواها.
- تحتفظ Flutter بنسخة محلية من قائمة المفضلة للعرض دون اتصال. الإضافة والإزالة تتطلبان اتصالاً بالخادم في هذه النسخة؛ لا تُنشأ عمليات مزامنة مؤجلة لتغييرات المفضلة عند انقطاع الشبكة.
- المزامنة المحلية تتم عند فتح قارئ الكتاب مع توفر الشبكة، أو عند حفظ موضع جديد. لا يوجد عامل مزامنة في الخلفية.
- مفتاحا التخزين الجديدان `book_pages_v2_*` و`book_page_v2_*` لا يُكتبان إلا بعد أن يؤكد API أن `offline_access_allowed=true`. عند رفض الإذن من الخادم تُمسح ذاكرة ذلك الكتاب. عند أول فتح بعد هذه الترقية تُحذف مفاتيح الصفحات القديمة غير المصنفة حسب الإذن، ولا تُقرأ.
- التخزين المحلي الحالي يستخدم `SharedPreferences` غير المشفر؛ لذلك لا يُستخدم للمواد السرية. إزالة البيانات المحلية بعد سحب الإذن تتطلب اتصالاً بالخادم كي يتعرف التطبيق على السحب.

## الاختبارات

تغطي اختبارات API التحقق من مفتاح الجهاز، عزل الأجهزة، تكرار الإضافة، حجب المحتوى غير الموثق، الرفض للحقول الزائدة، التحقق من رقم المجلد والصفحة، تحديث الموضع، واسترجاعه وإزالته.
